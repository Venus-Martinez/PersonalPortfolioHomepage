AWS Portfolio Website

A responsive personal software development portfolio built with HTML, CSS, and JavaScript, managed with Git and GitHub, and deployed using both GitHub Pages and Amazon Web Services.

View AWS Hosted Version View Source Code Back to Projects

Project Overview

This portfolio website serves as the central location for showcasing my software development projects, technical skills, education, and continued growth as a developer.

Rather than using a website builder or prebuilt portfolio platform, I developed the site directly with HTML, CSS, and JavaScript and use Git and GitHub to manage its source code and development history.

The portfolio has also become an ongoing cloud development project. In addition to being deployed through GitHub Pages, the website is hosted through Amazon Web Services using Amazon S3 static website hosting.

Purpose

The original purpose of the project was to create a professional location where I could organize and present my growing collection of programming and cloud-development projects.

As I continued learning new technologies, the portfolio itself became another project. Instead of only displaying what I had learned, I began applying those technologies directly to the website.

This allows the portfolio to evolve alongside my skills while also providing practical experience with development workflows, version control, deployment, cloud hosting, and serverless application architecture.

Development Process

The portfolio is developed locally using Visual Studio Code. HTML provides the site structure, CSS controls the visual design and responsive layout, and JavaScript adds dynamic functionality where needed.

Git is used to track changes to the project, while GitHub stores the remote repository and provides a public development history.

This workflow allows changes to be developed and tested locally before being committed and pushed to GitHub.

Version Control

Git and GitHub are used throughout development to manage changes to the website.

As new projects, pages, styles, and features are added, changes can be grouped into commits that document the progression of the portfolio over time.

GitHub also provides the source repository used for one of the site's public deployment methods through GitHub Pages.

AWS Deployment

The portfolio is also hosted through Amazon Web Services using an Amazon S3 bucket configured for static website hosting.

The website's HTML files, stylesheets, project pages, JavaScript, and image assets are uploaded to the S3 deployment and served as a static website.

Working with Amazon S3 provided hands-on experience with cloud storage, bucket configuration, static website hosting, object organization, and deploying web content outside of a traditional hosting platform.

Deployment Architecture

The same portfolio project can be delivered through two different hosting environments.

GitHub Pages provides a deployment directly from the GitHub-hosted source project, while Amazon S3 provides a separate AWS-hosted static deployment.

Using both platforms helped me understand the difference between source control, application development, and the infrastructure responsible for actually delivering a website to users.

Serverless Visitor Counter

The portfolio has expanded beyond a purely static website by incorporating a serverless visitor counter.

JavaScript running in the browser uses the Fetch API to request the current visitor count from an AWS Lambda function.

The Lambda function communicates with Amazon DynamoDB, where the visitor count is stored persistently. Each visit updates the stored count and returns the new value to the website as JSON.

The returned value is then displayed dynamically in the portfolio footer without requiring the entire webpage to reload.

Cloud Architecture

The visitor counter introduced a basic separation between frontend, backend, and persistent storage.

The static website acts as the frontend, AWS Lambda provides serverless backend logic, and Amazon DynamoDB provides persistent application data.

This was an important step beyond static hosting because it demonstrated how multiple cloud services can work together to provide dynamic functionality without requiring a traditional always-running server.

Challenges and Solutions

Moving beyond local development

One of the first challenges was understanding the difference between building a website locally and making that website publicly accessible.

Deploying through GitHub Pages and Amazon S3 gave me practical experience with two different approaches to publishing the same project.

Connecting frontend and backend services

Adding the visitor counter required the browser-based frontend to communicate with a separate AWS service.

JavaScript's Fetch API is used to request JSON from the Lambda backend, while CORS configuration allows the browser to communicate with the Lambda Function URL across different domains.

Persisting application data

A visitor count cannot rely only on browser memory because the value needs to remain available across users and page loads.

Amazon DynamoDB provides persistent storage for the count, allowing the Lambda function to retrieve and update the value independently of the frontend.

Troubleshooting unexpected requests

During development of the visitor counter, browser behavior caused additional requests that initially resulted in the count increasing more than expected.

Investigating application behavior and AWS logs helped identify the cause and refine the Lambda logic so that unintended requests would not affect the visitor count.
