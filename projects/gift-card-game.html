Gift Card Game

A Java console application that simulates a multiplayer gift card game using object-oriented programming, file input, collections, randomized gameplay, elimination rules, and calculated winner selection.

View Source Code Back to Projects

Project Overview

The Gift Card Game is a Java console application built to simulate a complete multiplayer game from initial setup through winner selection.

The program loads gift card data from an external text file, creates participants, distributes cards, calculates values, performs elimination checks, simulates randomized card swaps, and determines the final winner.

The project was designed using multiple Java classes so that game data, participant behavior, card management, and overall game control are separated into distinct responsibilities.

Purpose

The goal of this project was to apply core object-oriented programming concepts to a larger application involving multiple interacting classes.

Instead of placing all logic inside a single program file, the application separates the game into specialized components that work together to manage cards, players, game rules, and user interaction.

The project also provided hands-on experience with file input, ArrayLists, randomization, validation, nested loops, comparisons, and formatted console output.

How the Game Works

When the program starts, gift card information is loaded from an external data file and shuffled into a random order.

The user then selects between one and five participants and enters a name for each participant. Each participant receives three gift cards from the shuffled collection.

The application calculates the combined value of each participant's cards and then applies the first elimination rule.

Initial Elimination

After the first three cards are distributed, the total calculated value of each participant's cards is evaluated.

Any participant whose combined calculated value is greater than $3,000 is removed from the game.

Participants who remain continue into the random card-swapping phase.

Random Card Swapping

Each remaining participant receives two opportunities to swap one of their existing gift cards.

For each opportunity, the program randomly decides whether a swap will occur. If a swap is selected, the application randomly chooses one of the participant's existing cards and replaces it with the next available card from the Barrel.

Because both the initial card order and the swap decisions are randomized, separate executions of the program can produce different hands, eliminations, and winners.

Final Elimination

After the card-swapping phase, each remaining participant's cards are checked for duplicate companies and duplicate monetary values.

A participant is eliminated if two or more of their gift cards share the same company or the same monetary value.

Participants who pass this final check remain eligible to win the game.

Winner Selection

Once the elimination phases are complete, the application compares the remaining participants.

The participant with the lowest combined calculated gift card value is selected as the winner.

If every participant has been eliminated, the program reports that no winner remains.

Object-Oriented Design

The project is divided into five primary Java classes, with each class responsible for a specific part of the application.

GiftCard

The GiftCard class represents one individual card. It stores the card's category, company, monetary value, and assigned point value.

It also calculates the weighted value of the card by multiplying its monetary value by its point value.

Participant

The Participant class represents one player in the game and stores that participant's name and collection of GiftCard objects.

It also calculates the combined value of all cards currently assigned to the participant.

Barrel

The Barrel class manages the complete collection of available gift cards.

It reads card information from the external data file, creates GiftCard objects, stores them in an ArrayList, shuffles the collection, and returns cards one at a time as the game progresses.

GameMaster

The GameMaster class controls the primary game rules and coordinates the other classes.

It manages participants, deals cards, performs elimination checks, runs the card-swapping phase, determines the winner, and displays game results.

GiftCardGameTest

GiftCardGameTest contains the program's main method and serves as the entry point for the application.

It gathers participant information from the user and calls the appropriate GameMaster methods in the correct order to complete the game simulation.

External Gift Card Data

Gift card information is loaded from UpdatedGiftCardData.txt rather than being hardcoded directly into the Java classes.

Each entry contains a category, company, monetary value, and point value.

Categories in the current data set include entertainment, restaurants, retail, gas, online shopping, beauty and spa, and sports.

Using an external data file separates the game data from the application logic and makes the collection easier to update independently of the Java source code.

Development Process

The application was developed in Java using a multi-class object-oriented structure.

The project required coordinating several objects while maintaining a clear separation between data, player state, card management, gameplay rules, and console interaction.

Collections such as ArrayList are used to manage participants and gift cards, while Java's Collections and Random utilities support shuffling and randomized gameplay decisions.

Challenges and Solutions

Coordinating multiple classes

One challenge was determining which responsibilities belonged in each class and how those classes should communicate with one another.

Separating card data, participants, card storage, and game control into different classes helped keep the application easier to understand and maintain.

Managing card state

The program needed to ensure that cards were drawn from the shuffled collection in order without repeatedly returning the same card.

The Barrel class uses a pointer to track the next available card and advances that pointer whenever a card is drawn.

Handling participant elimination

Participants need to be removed from the active collection during multiple stages of gameplay.

During elimination checks, the participant list is traversed in a way that allows entries to be safely removed without unintentionally skipping other participants.

Randomized game behavior

The game required random behavior while still following consistent rules.

Randomization is used for card order, swap decisions, and the selection of which card is replaced, while the elimination and winner rules remain deterministic.
